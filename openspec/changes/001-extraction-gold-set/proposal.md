# 001 — Extraction gold set

Status: **applied** (v9.1+1)
Decided by: user, 2026-10-18
Trial: first change written proposal-first, to judge whether the discipline pays.

## Why

339 tests check files, documents and consistency. Not one checks that following
`afc-cards` produces good knowledge. The spec can be perfectly self-consistent
and the extraction still bad, and today nothing would say so.

The retrieval half already has this: `config/query-cases.yaml` plus
`run_query_benchmark.py` compare against an accepted baseline. The extraction
half has no equivalent, so a change to a skill's wording — this session made
many — ships with no evidence it did not make extraction worse.

## What is actually assertable

A Card is model-authored prose. Asserting its text would test wording, fail on
every harmless rewrite, and teach everyone to ignore the suite. So the gold set
asserts the two things the architecture says are not free:

1. **Literal preservation.** A named string that exists in the source must
   appear verbatim in some Evidence Record. `Tải lên thất bại`, `E102`, `100`,
   a formula with no cached value. This is checkable because Evidence is defined
   as the literal layer.
2. **Claim coverage.** Each expected claim must be covered by at least one Card
   that cites the right Source Unit, matched on required terms rather than
   wording. A claim may be worded any way; it may not be missing.

Plus two negatives, which matter more than either:

3. **Fabrication.** A fact the source does not state must not appear. The source
   says `期限內`; a Card claiming `30 天` is the failure this whole package is
   built to prevent, and nothing currently detects it.
4. **Accounting.** Every selected Source Unit has exactly one disposition.

And one thing that needs no model at all:

5. **Step 0 is deterministic.** Parsers plus `build_context_candidates.py` give
   the same source map every time, so the gold set asserts it exactly. This is
   the cheap half and it catches parser regressions on its own.

## Sources

Synthetic but realistic, generated by a committed script rather than checked in
as binaries: a `.docx` with a nested table and a Vietnamese error message, an
`.xlsx` with a merged header and a formula cell with no cached value, and a
`.md` article with sections. No real company specs, and nothing from the PMP
material — this repository is public, and an Evidence Record is by design a
near-complete copy of its source.

The OCR case is optional: it runs when Tesseract and `chi_tra+eng+vie` are
present and skips otherwise, so the gold set still runs on a machine without
them.

## Out of scope

- Scoring Card prose quality, or anything that would fail on a rewrite.
- A baseline-comparison mode. Grade against the gold expectations first; add
  run-to-run comparison only once the first numbers exist.
- Replacing `evaluate_card_health.py`. Health measures a run against itself;
  this measures a run against a known answer. Both stay.

## Verdict on the trial

Worth keeping for a change of this size. Writing "what is assertable" before
building killed the obvious wrong design — asserting Card text — before any code
existed, and the out-of-scope list stopped two scope creeps (baseline
comparison, prose scoring). For the three-line ratchet fixes earlier in this
session it would have cost more than the fix.

Kept as a plain directory, not an OpenSpec install: the artifacts carry the
value, and a Node toolchain in a Python package is a dependency users would
inherit. `build_release.py` excludes `openspec/` from the shipped archive.
